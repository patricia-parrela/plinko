Plinko Reward Engine: how I built it

By Patricia Parrela · Oct 19 2026

Mobile first · 390 px Interactive prototype (React) Figma library + specs Sound designed

The brief

Users earn tickets in normal gameplay and redeem them in a Plinko pop-up over the homepage, to win secondary rewards.

Goal: retention and a second dopamine loop that gives people a reason to come back every day.

Process

  1. Pick a theme that means luck

    I chose the Japanese lucky cat (maneki-neko). It is friendly, stands for fortune, and it gives the game a character who can react like wave, hold the ball, celebrate. The structure is theme-agnostic, so the same engine can be re-skinned for another campaign by swapping tokens and art.

  2. Plan the experience before any pixels

    I wrote down the whole experience first:

    • Screens: homepage entry point, onboarding, game, win, out of tickets.
    • Risk levels: two modes. Classic (more wins, up to 5K GC) and Lucky Rush (rarer wins, up to 50K GC).
    • Prizes: Gold Coins, Free Spins and extra Plinko tickets.
    • Every interaction: what the user taps, what moves, what they hear, and what happens next.

  3. Claude Code

    Turn the spec into a working structure

    I gave the written spec to Claude Code and built in phases: tokens first, then components with explicit states, then the game, then polish. Every color, spacing and timing value lives in one tokens file, so design changes never touch component code.

  4. Physics research

    Make the drop feel real + suspense

    The first ball moved on rails and felt fake. I researched how Plinko physics is done in JavaScript (gravity, air drag, bounce, peg collisions, a little randomness) and had a lightweight physics engine built into the game using Matter.js. I kept iterating on speed and bounce until the fall felt natural.

    • Suspense: in the last 3 rows, lanterns the ball can no longer reach go dark, and the last 2 rows play in slow motion.

  5. Gemini Pro

    Art direction and assets

    I defined the look (neon Tokyo night, gold, pink and purple, glossy 3D) and generated the art in Gemini Pro with specific prompts: the cats, lanterns, coin, slot machine, ticket, win frame and backgrounds. I brought them into Claude Code and replaced placeholders one by one.

  6. Gemini Pro · Web Audio

    Music and sound effects

    I generated the background track in Gemini Pro with specific instructions, and added a Japanese palette of effects (chimes, gong, flute) mapped to each moment: every peg hit climbs one note, a taiko roll builds suspense, a fanfare sized to the prize plays on the win. There is a mute button.

  7. Play-test and iterate

    I played it on a phone-sized screen constantly and fixed what felt wrong. A few examples:

    • The cat waving left and right looked like it was aiming the ball, so now it only pulses the ball and waves when you win.
    • The winning lantern lit up before the ball arrived, which made the game look rigged. I removed it.
    • The win popup now waits 1 second so you see the cat celebrate.
    • The game screen never scrolls, and the onboarding keeps one height so nothing jumps.

  8. Claude Code · Figma plugin

    Design system and handoff

    I had a Figma plugin built that generates the library from the code: token variables, components with variants (buttons, mode toggle, lanterns, ball and pegs, win popup), each with specs for engineers covering props, states, animation and sound triggers, plus the game odds, the sound map and all screens.

What I would test next

  • Mode choice: share of players picking Lucky Rush, and whether it changes return rate.
  • Loop strength: drops per session and how often players use all their tickets.
  • Daily return: D1 and D7 retention for players who tried Plinko against those who did not.
  • Prize mix: whether Free Spins or tickets drive more follow-on play than coins.
